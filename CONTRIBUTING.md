# Contributing

Propose focused changes, document their effects on behavior, and verify the affected cases. Do not include real configuration files or secrets.

Use [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/), for example `fix: correct the path`, `feat: add an option`, or `docs: clarify installation`. Mark breaking changes with `!` after the type or with a `BREAKING CHANGE:` footer.

After the first stable release, `fix` normally indicates a patch increment and `feat` a minor increment; a breaking change requires a major increment. Other types do not by themselves require an increment. Commits guide the choice, but actual compatibility and all changes included in the release must be assessed. See the README for the release procedure.
